# Audiovisual scene gap audit

This audit preserves the PRD's B01–B17 identifiers and corrects their scope
against release `v0.14`, commit
`71d89b1735a523ffeb54c5d3755aff54578c6612`, inspected on 31 October 2026.
Proposed changes in the implementation series are identified separately; they
are not described as merged or deployed. AV-01–AV-10 are the implementation
work packages, not ten equally sized changes.

**Observed** means supported by repository source or a focused test.
**Proposed** means required behavior that has not yet been implemented.
**Unverified** means an execution or quality claim still needs measured evidence.
A deliberate capability limit is not automatically a bug. Browser screenshots,
mocked provider tests, and valid workflow JSON do not establish live GPU output
or hosted project continuity.

## Decisions carried into implementation

- Use Camera as the interaction reference: preview first, compact Music,
  Scene and Look controls, clear selection and readiness, one primary action
  per stage, and optional Advanced controls. Build scene and Render video
  operate on the same project. The initial UI improvements do not imply that
  the full hosted workflow is available.
- Prove the source scene and geometry-based CPU sound first. Keep AKUSPACE as
  a distinct creative sound option; the creator's preference for its cathedral
  reverb is a listening preference, not evidence of dynamic geometric accuracy.
  An optional serial CPU → subtle AKUSPACE experiment follows the core proof.
- Derive the Klein appearance reference from the captured scene's exact first
  frame. Preserve its camera and architecture and inspect the styled result;
  using an image model does not itself guarantee alignment.
- Design an ordered, variable-length scene-state contract. Three visible
  states are the initial example, not the schema limit. Start with one room
  and bounded prop motion; add procedural voxel-pyramid and Rubik-like recipes
  next, then a seeded skyscraper/street scene through the same interfaces.
  City-map ingestion, outdoor acoustics and arbitrary mesh topology are separate
  capabilities.
- Begin without new training. First isolate capture, look alignment, guide
  strength and audio-conditioning failures using the qualification matrix.

The proposed B09 patch is covered by
[Apply room provenance PR](https://github.com/koshimazaki/genobi/pull/18):
capture room A, edit to B, process A; explicitly capture B to process B; reject
invalid receipts; ignore stale receipt resolution; prevent import after the
take or project changes. The ordinary editor often clears a take on edits, so
the baseline finding is an invariant failure for retained/restored or
asynchronous take contexts, not a claim that every normal edit exposes the
same stale button. See [the action's documented behavior](world-builder-sound.md).

## Additional requirements, without inventing more baseline bugs

### Persistent restore and agent memory have different jobs

[Studio undo](https://github.com/koshimazaki/genobi/blob/release/v0.14/src/studio/store.ts) retains at most twenty in-memory Bundle
snapshots. [Agent memory](https://github.com/koshimazaki/genobi/blob/release/v0.14/server/agent-memory.ts) and
[shared memory state](https://github.com/koshimazaki/genobi/blob/release/v0.14/shared/memory/state.ts) retain decisions and progress,
not every historical scene and media byte. AV-05 must retain immutable
revisions and their asset pins; restore creates a new revision with links to
the chosen source. AV-07 records why a change happened and what was reviewed.
Neither should promise unlimited retention. Test restore after reload, missing
bytes, concurrent completion and revoked project access.

### Reuse the paid-run safeguards

The existing deployment tests cover session ownership, quote binding, one-use
reservations and uncertain-submission handling. Extend these paths rather than
adding an agent-only execution route. Near-quota arrival of video plus audio/IR
companions, target deletion and output-copy failure are required new-system
tests; they are not all reproduced baseline defects. Retain the entire output
group until its project commit succeeds or a declared recovery policy applies.

### Stage qualification to avoid a dependency cycle

AV-02 milestone **A** supplies the offline kit and a baseline feasibility pilot
using current supported captures or a separately documented deterministic test
guide. It does not depend on the production variable-state engine. AV-03 and
AV-04 can develop their contracts alongside A and use its evidence to constrain
the supported motion vocabulary. AV-02 milestone **B** then qualifies their
final state/capture implementation and the AV-10 template. Passing A is not a
release pass. CPU algorithm tests can begin before managed jobs; hosted
sound-only delivery additionally needs AV-06. AKUSPACE/hybrid qualification is
optional and does not block a proven CPU-first release.
